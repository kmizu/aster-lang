# ASTER v0.1.0 Release and GitHub Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish ASTER `v0.1.0` with a validated Operational Amber GitHub Pages site and verified Linux, macOS, and Windows CLI archives.

**Architecture:** Keep release concerns outside ASTER's semantic/runtime crates. A framework-free `site/` is deployed by a least-privilege Pages workflow, while a tag-only matrix workflow builds native archives and a single gated publish job creates the GitHub Release. Repository-owned shell checks make the site, workflow, asset-name, version, and legal contracts locally auditable.

**Tech Stack:** Rust 1.96, Bash, static HTML/CSS/vanilla JavaScript, GitHub Actions, GitHub Pages, GitHub CLI.

## Global Constraints

- The released version is exactly `0.1.0` and the annotated tag is exactly `v0.1.0`.
- The release commit is the merged `main` commit; history is never rewritten or force-pushed.
- The site URL is exactly `https://kmizu.github.io/aster-lang/`.
- Release assets cover Linux x86_64 musl, macOS Apple Silicon, macOS Intel, and Windows x86_64 MSVC.
- Each archive contains only the executable, `README.md`, and `LICENSE`.
- The site uses no external fonts, images, scripts, trackers, analytics, packages, or runtime network calls.
- Copy must say that ASTER 0.1 is experimental and fixture-backed, not production-ready.
- No ASTER syntax, semantic, IR, runtime, persistence, or security behavior changes.
- Every external mutation is gated by a passing local or GitHub check and verified afterward.

- [ ] **Step 3: Add the Pages workflow**

Trigger on `main` changes to `site/**` or the workflow and on manual dispatch.
The build job has `contents: read`, runs the site checker, calls
`actions/configure-pages@v5`, and uploads only `site/` with
`actions/upload-pages-artifact@v4`. The dependent deploy job targets the
`github-pages` environment and alone grants `pages: write` and
`id-token: write`, then calls `actions/deploy-pages@v4`.

- [ ] **Step 4: Add the tag-only native release workflow**

Use four explicit matrix entries with the runner/target/format values from the
design. Every job checks out the tag, installs Rust 1.96 and the target, runs
`cargo test --workspace --all-features`, builds `aster-cli`, stages exactly the
binary/README/LICENSE, creates the declared archive, and uploads it with
`actions/upload-artifact@v4`.

The dependent `publish` job on `ubuntu-24.04` downloads all archives with
`actions/download-artifact@v4`, asserts exactly four archives, creates
`SHA256SUMS`, validates every checksum, and runs:

```bash
gh release create "$GITHUB_REF_NAME" dist/* \
  --repo "$GITHUB_REPOSITORY" \
  --title "ASTER $GITHUB_REF_NAME" \
  --notes-file docs/releases/v0.1.0.md \
  --verify-tag
```


Expected: all PASS.
