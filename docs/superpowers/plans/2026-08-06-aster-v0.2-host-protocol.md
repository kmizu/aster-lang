# ASTER v0.2 Host Protocol Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release ASTER v0.2.0 with a versioned, two-phase stdio host protocol
that lets Codex drive real governed effects while ASTER retains capability,
budget, permit, trace, snapshot, reconciliation, and replay control.

**Architecture:** Refactor the fixture record loop into a pure
`RecordSession`, then layer a transport-independent `HostSession` over it.
`aster-cli` owns bounded JSONL I/O and artifact persistence; the VM, protocol
state machine, and replay retain no ambient I/O.

**Tech Stack:** Stable Rust 1.96, serde/serde_json, clap, tempfile, canonical
SHA-256, Bash contract tests, GitHub Actions, static HTML/CSS.

## Global Constraints

- Preserve every invariant in repository `AGENTS.md`.
- Keep dependency direction exactly
  `diagnostics <- syntax <- semantics <- ir <- runtime <- cli`.
- Add no network, TLS, process-execution, MCP, provider-SDK, or plugin-loading
  dependency to the runtime.
- Keep `unsafe` and reachable production panic/placeholder APIs forbidden.
- Source syntax stays ASTER 0.1; distribution/runtime become 0.2.0; host
  protocol schema starts at 1.
- Existing fixture execution and driver-free replay stay compatible.
- Protocol input is UTF-8 JSON Lines, at most 1 MiB per line, with unknown
  fields rejected at every nesting level.
- Stdout contains protocol frames only; diagnostics use stderr.
- Only `model_tokens` and `money_microunits` are host-declared usage.
- Persist a sealed snapshot and trace checkpoint before `execute_grant`.
- Replay accepts no host transport and never invokes a driver.
- Tests/examples use synthetic data and temporary workspaces only.
- Every implementation task follows RED → GREEN → focused verification →
  commit. Final verification is `./scripts/check.sh`.

```rust
#[derive(Clone, Debug, Eq, PartialEq)]
pub struct AdmittedEffect {
    pub request: EffectRequest,
    pub maximums: BTreeMap<String, u64>,
    pub snapshot: MachineSnapshot,
    pub snapshot_hash: String,
    pub trace_position: u64,
    pub trace_hash: String,
}

#[derive(Clone, Debug, Eq, PartialEq)]
pub enum RecordProgress {
    AwaitingAdmission(EffectRequest),
    AwaitingResolution(Box<AdmittedEffect>),
    Completed(RunOutcome),
}

pub struct RecordSession { /* machine, trace, snapshots, explicit phase */ }

impl RecordSession {
    pub fn start(program: Program, start: StartRequest) -> Result<Self, RunError>;
    pub fn restore(
        program: Program,
        snapshot: MachineSnapshot,
        trace: Trace,
    ) -> Result<Self, RunError>;
    pub fn progress(&mut self) -> Result<RecordProgress, RunError>;
    pub fn admit(
        &mut self,
        request_hash: &str,
        maximums: BTreeMap<String, u64>,
    ) -> Result<AdmittedEffect, RunError>;
    pub fn resolve(&mut self, value: &EffectResolution) -> Result<(), RunError>;
    pub fn trace(&self) -> &Trace;
    pub fn snapshots(&self) -> &[MachineSnapshot];
    pub fn finish(self, outcome: RunOutcome) -> RecordResult;
    pub fn fail(self, error: RunError) -> RecordFailure;
}
```

`progress` drains audit events and stops on yield/terminal. `admit` verifies the
pending request hash, reserves maximums, appends budget evidence, checkpoints
and seals a snapshot, and records `snapshot_written`. `resolve` requires the
admitted phase, appends/supplies the exact resolution, drains audit, and settles
usage. Add non-payload `RunError::SessionPhase`.

Rewrite `record_run_evidenced` as an adapter: preview only in
`AwaitingAdmission`, driver resolve only in `AwaitingResolution`, and convert
all controlled errors through `session.fail`.
